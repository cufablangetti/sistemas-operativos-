Paginación: un espacio lineal cortado en trozos iguales

pág. 0 · código
pág. 1 · código + principio de datos
pág. 2 · datos
pág. 3 · datos + tabla de símbolos
pág. 4 · pila

Los cortes caen donde caen: una página puede mezclar código y datos. Su contenido es «accidental».

  • + Es invisible para el programador.
  • + Todas las unidades son de tamaño fijo: no hay fragmentación externa, solo interna (½ página).
  • + Da un espacio lineal grande sin comprar más RAM.
  • − No se puede proteger «el código» aparte de «los datos»: el programador tendría que saber dónde caen los límites de página.
  • − Las tablas que crecen pueden chocar entre sí (fig. 3-31).
  • − Compartir solo una parte (una biblioteca) es más complicado: hay que simular segmentos.

Segmentación: muchos espacios independientes, cada uno desde 0

segmento 0 · código · 0 a 12K · solo ejecución
segmento 1 · tabla de símbolos · 0 a 20K · L/E
segmento 2 · constantes · 0 a 4K · solo lectura
segmento 3 · árbol sintáctico · 0 a 16K · L/E
segmento 4 · pila · 0 a 8K · L/E, crece

Cada segmento es una entidad lógica que el programador conoce, y guarda un solo tipo de cosa.

  • + Cada tabla crece o se achica sin chocar con las demás.
  • + Protección por tipo: el código solo se ejecuta y en los datos no se puede saltar.
  • + Si se recompila el procedimiento del segmento n, no cambian las direcciones de los demás (se llama con (n, 0)).
  • + Se comparte un segmento entero (por ejemplo, la biblioteca gráfica).
  • − El programador tiene que estar consciente: las direcciones son de dos partes.
  • − Tamaño variable → fragmentación externa (tablero de ajedrez, pestaña 2).
  • − Un segmento grande puede no entrar entero en memoria → MULTICS y Pentium lo paginan.

Traducción paso a paso

Ideas clave para el examen

  • Un segmento es un espacio de direcciones independiente, de 0 a un máximo, con longitud variable que puede cambiar durante la ejecución. Es una entidad lógica que el programador conoce (un procedimiento, un arreglo, una pila). La dirección es bidimensional: (segmento, dirección dentro del segmento).
  • 🧠 La protección «tiene sentido» en segmentación y no en paginación porque cada segmento guarda un solo tipo de objeto; el contenido de una página es accidental.
  • ⚠️ Páginas de tamaño fijo vs. segmentos de tamaño variable. Por eso la segmentación pura sufre fragmentación externa (efecto tablero de ajedrez), que se arregla con compactación, y la paginación solo sufre fragmentación interna.
  • En la fig. 3-33 todo es «No / Sí», salvo «¿puede exceder la memoria física?», que es Sí en las dos. Los segmentos grandes se paginan (MULTICS, Pentium) para juntar las ventajas de las dos técnicas.
