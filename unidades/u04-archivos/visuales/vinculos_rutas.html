    Lado a lado

    Vínculo duro (otra entrada de directorio al MISMO nodo-i)
    • + No gasta nodo-i ni bloque extra; es tan rápido como el original.
    • + Si el dueño borra su nombre, el archivo sigue vivo para B.
    • − El dueño sigue siendo C, y la cuota se le cobra a C hasta que B lo borre (fig. 4-17c).
    • − Solo dentro del mismo sistema de archivos (el número de nodo-i es local); en general no se permite a directorios.
    Vínculo simbólico (un archivo tipo LINK que contiene una RUTA)
    • + Puede cruzar sistemas de archivos y hasta apuntar a otra máquina.
    • + Solo el dueño tiene el puntero al nodo-i: si C borra, el archivo se destruye de verdad.
    • − Más lento: hay que leer la ruta y recorrerla componente por componente.
    • − Gasta un nodo-i (y quizás un bloque) más; si el original desaparece, queda colgado.

    Ideas clave y frases de examen

    • Vínculo duro = otra entrada (nombre, nº de nodo-i) al mismo nodo-i; sube el contador. Borrar es unlink: baja el contador, y el archivo se libera recién cuando llega a 0.
    • ⚠️ Si C borra un archivo con un vínculo duro de B, el archivo no desaparece: queda con contador 1, sigue siendo de C y le sigue contando en la cuota.
    • ⚠️ Si C borra el original de un vínculo simbólico, el vínculo queda colgado: «No such file or directory». Borrar el simbólico no le hace nada al original.
    • 🧠 Buscar /usr/ast/mbox alterna nodo-i → bloque de directorio → nodo-i → …. Cada componente cuesta 2 lecturas si no hay caché; por eso existe la caché de nombres.
